1. Nintendo Switch

95
Recomendação: para começar no Switch o kit mínimo é hekate + Atmosphère (boot e CFW), sphaira (menu e instalador), JKSV (backup de saves) e aio-switch-updater (manter tudo atualizado). Use sempre emuMMC (sistema separado no SD) para não arriscar o sistema original.
Estrutura básica do cartão SD
SD:/
├─ atmosphere/        ← Atmosphère (CFW)
│  └─ contents/       ← mods e traduções (LayeredFS)
├─ bootloader/        ← hekate (config em hekate_ipl.ini)
├─ switch/            ← apps homebrew (.nro)
├─ config/            ← configurações dos apps
└─ payload.bin / hbmenu.nro

1.1 Custom firmware e boot (o "desbloqueio")

  1. Console em modo RCM (jig no trilho direito + Volume+ + Power) ou modchip.
  2. No PC, abra o TegraRcmGUI (ou Rekado no Android) e envie o hekate_ctcaer_x.x.x.bin.
  3. No hekate: Tools → Backup eMMC (guarde esse backup!), depois emuMMC → Create.
  4. Volte e escolha Launch → Atmosphère (emuMMC).

1.2 Dump, chaves, formatos NSP/XCI/NCA (abrir e reempacotar jogos)

Abrir um NSP e extrair o RomFS (onde ficam textos, fontes e imagens)
# 1) separar o NSP em NCAs
hactool -t pfs0 --outdir=nsp_ext jogo.nsp

# 2) achar a NCA de programa (a maior) e extrair RomFS/ExeFS
hactool -k prod.keys --titlekey=<chave_do_ticket> \
  --romfsdir=romfs --exefsdir=exefs nsp_ext/xxxx.nca

# o mesmo com nstool (mostra mais informações)
nstool -v nsp_ext/xxxx.nca
Comprimir e descomprimir
nsz -C jogo.nsp        # NSP → NSZ (menor)
nsz -D jogo.nsz        # NSZ → NSP
nsz --verify -D jogo.nsz
Recomendação: as chaves (prod.keys/title.keys) se tiram do seu próprio console; ninguém pode distribuí-las. Guarde-as numa pasta fixa (ex.: ~/.switch), que é onde hactool, nstool e NSC_BUILDER procuram por padrão.

1.3 Mexer nos arquivos dos jogos (tradução, texturas, modelos)

Testar tradução/mod sem reempacotar o jogo (LayeredFS)
SD:/atmosphere/contents/0100ABCD12345000/   ← Title ID do jogo
   ├─ romfs/   ← só os arquivos alterados, mesma estrutura do RomFS original
   └─ exefs/   ← main, main.npdm (se mexeu no código)
Automatizar com Python (oead)
import oead

dados = open("Msg_USen.product.sarc.zs","rb").read()  # .zs = zstd; .szs = yaz0
sarc = oead.Sarc(oead.yaz0.decompress(open("Layout.szs","rb").read()))
for f in sarc.get_files():
    print(f.name, len(f.data))

byml = oead.byml.from_binary(open("Dados.byml","rb").read())
print(oead.byml.to_text(byml))   # vira YAML legível

13. Para quem traduz jogos: o que usar

  1. Abrir/fechar Switch: hactool ou nstool (abrir NCA/NSP com as suas chaves), NSC_BUILDER (juntar/converter/limpar ticket), nsz (comprimir), Atmosphère LayeredFS (testar sem reempacotar).
  2. Texto, fonte e textura first-party Nintendo: Switch-Toolbox (BNTX, BFFNT, MSBT, BFLYT), oead/byml-v2/sarc (Python, dá para automatizar), Kuriimu2.
  3. Pokémon: pkNX (dados de Switch), PKHeX (testar saves), PokeAPI (conferir nomes oficiais em vários idiomas), decompilações pret (traduções de GB/GBA/DS feitas no código-fonte).
  4. 3DS/DS: 3dstool, Project_CTR (makerom/ctrtool), Tinke, DS-Pokemon-Rom-Editor, Kuriimu2.
  5. Testar no PC: Azahar (3DS), melonDS (DS), Dolphin (GC/Wii), Cemu (Wii U), mGBA (GBA).
  6. Organização: rom-properties (Title ID e nome no Explorador), titledb (lista de Title IDs).
  7. Capturar prints para revisão: SysDVR (tela do Switch no PC).
